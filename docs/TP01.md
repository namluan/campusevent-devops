# TP 01 : une CI observable et bloquante

TP réalisé sur CampusEvents (Node.js) au lieu de Rental (Java et Python).

| Sujet | Ici |
|---|---|
| `car-rental-service` | `events-service` |
| `pricing-service` | `bookings-service` |
| Gradle test, Pytest | `node --test` |
| Checkstyle, Ruff | ESLint et Prettier |
| `checkpoint/00-starter` | `main` avant le TP (aucun workflow) |

## Les contrôles

```text
tests ────┐
          ├──> image Docker      (un graphe par service)
qualité ──┘
secrets                          (indépendant)
```

| Contrôle | Risque couvert | Entrée | Sortie | Timeout |
|---|---|---|---|---:|
| `Events tests`, `Bookings tests` | Régression du comportement | Code, tests, lockfile | `junit.xml` | 10 min |
| `Events quality`, `Bookings quality` | Code mort, style non partagé | Code, config ESLint et Prettier | `eslint.html` | 10 min |
| `Events Docker image`, `Bookings Docker image` | Livrable impossible à construire | Dockerfile, code | Image, publiée sur `main` seulement | 15 min |
| `Secret detection` | Secret versionné | Historique Git | `gitleaks.sarif` | 10 min |

## Choix

- **Règles ESLint :** imports et variables inutilisés, accolades obligatoires, instructions vides, 100 caractères par ligne, imports triés. Prettier vérifie le formatage.
- **Exceptions :** une seule locale, dans `bookings.test.js` : Prettier ne coupe pas un import à un seul élément. Les paramètres de fonction inutilisés sont acceptés, car Express reconnaît un gestionnaire d'erreurs à ses quatre paramètres.
- **Tests de bookings :** ils démarrent le vrai serveur gRPC de `events-service`. Le job installe donc les deux services, et un changement d'`events-service` relance aussi ce workflow sur `main`.
- **Permissions :** `contents: read` par défaut. `packages: write` existe seulement dans le job image.
- **Publication :** la connexion à GHCR et le `push` sont conditionnés à un push sur `main`. Une PR construit l'image sans la publier.
- **Cache :** npm (clé sur le lockfile) et couches Docker par service.
- **Concurrence :** un nouveau push annule l'exécution précédente de la même branche.

## Pourquoi pas de filtre `paths` sur `pull_request`

Si le filtre écarte le workflow, le contrôle n'est jamais créé. S'il est obligatoire, il reste en attente et la PR ne peut pas être intégrée. Le filtre est donc gardé seulement sur les pushes vers `main`.

À l'inverse, un job sauté par `needs` compte comme réussi pour GitHub. Il faut donc rendre obligatoires les tests et la qualité, pas seulement l'image.

## Secrets

Gitleaks est lancé en ligne de commande, car l'action officielle ne lit que les commits de la PR. `--log-opts=HEAD` limite l'analyse à l'historique de la branche : une branche jetable ne bloque pas les autres PR. `--redact` masque les valeurs dans les logs.

- **Supprimer la ligne** la retire de la dernière version, mais elle reste dans l'historique.
- **Révoquer le secret** le rend inutilisable. C'est la première chose à faire, car il a pu être copié.
- **Réécrire l'historique** retire la valeur du dépôt, mais change les commits, oblige les autres à resynchroniser, et n'efface ni les clones ni les forks.

Vérifié en local dans un dépôt jetable hors du projet : une fausse clé générée au hasard est détectée même après la suppression de la ligne.

## Reproduire en local

```powershell
python scripts/course.py install
python scripts/course.py verify
```

`verify` lance les tests puis la qualité, s'arrête à la première erreur et retourne 1. Elle ne construit pas les images et ne lance pas Gitleaks.

## Observer un échec

Une assertion de `events.test.js` a été modifiée, puis rétablie dans le commit suivant ([exécution rouge](https://github.com/namluan/campusevent-devops/actions/runs/45598428105)).

1. **Job en échec en premier :** `Events tests`, à l'étape « Run tests ». `Events Docker image` est sauté, et les cinq autres contrôles restent verts.
2. **Ligne qui identifie la cause :** `events.test.js:36`, test « crée puis liste un événement » : `2 !== 3`.
3. **Rapport disponible :** oui. L'étape « Upload test report » réussit malgré l'échec, et `events-test-report` est conservé 7 jours.
4. **Temps avant le retour :** 16 secondes pour le job, 21 secondes depuis le lancement.

## Limites

- Le frontend n'a pas encore de contrôle en CI.
- Les actions sont référencées par version majeure, pas par SHA (TP 02).
